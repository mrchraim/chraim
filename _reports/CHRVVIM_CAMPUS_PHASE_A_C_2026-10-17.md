## 3) المرحلة C — الاستخراج (منجَز، قابل للتكرار)

### الأدوات المُنشأة (كود فعلي يعمل)
- `ingest/extract.py` — مُستخرِج عام: **PDF (pypdf)، DOCX، PPTX، XLSX، CSV، TXT**.
  - حضور التكرار ببصمة نصّية (SHA-1)، تصفية بالنمط، تقرير `report.md` + `manifest.json` + `text/<slug>.txt`.
- `ingest/parse.py` — مُحلِّل يحوّل النصّ إلى بنية: توزيع أفواج، برنامج تقويمات، استعمال زمن.

### نتائج تشغيل الاستخراج (فعلي)
```
{"files": 35, "ok": 11, "duplicate": 22, "empty": 2, "error": 0}
```
- **11 وثيقة فريدة** استُخرجت بنجاح، **22 تكراراً** اكتُشف (تأكيد أن «العشرين» تشمل نسخاً مكرّرة)، **2 تحتاج OCR**، **0 فشل**.
- **اللغة العربية استُخرجت سليمة تماماً** (تحقّق يدوي): أسماء الأساتذة، القاعات، الأفواج، المواد، الأوقات.

### البيانات المؤكّدة المستخرَجة (أمثلة حقيقية)

**قاعدة توزيع الأفواج (مؤكّدة من وثيقتين رسميتين):** الترتيب **أبجدي بنطاقات أسماء**.

- S4: 14 فوجاً (A–N): `A: A'MIL→AIT BOUDDI` … `N: ROUISSAME→ZYATI`
- **ملحوظة رسمية من الوثيقة:** «الأسماء المركّبة (مع فراغ) تأتي دائماً قبل الأسماء غير المركّبة» / «Les lettres avec Espace (détachées) viennent toujours avant les lettres sans espace (attachées)».

**استعمال الزمن — التحليل النهائي (بعد تحسين المُحلِّل):**

| الجدول | حِصص | أيام | أفواج | قاعات | مواد | أسطر أساتذة مرشّحة |
|---|---|---|---|---|---|---|
| S1 (`3461_…`) | 5 | 6 | 20 (A–T) | 18 | 7 | 35 |
| S2 (`3995_…8558`) | 5 | 6 | 20 (A–T) | 30 | 7 | 35 |
| `استعمال زمن فوجB` | 1 | 3 | 0 | 5 | 0 | 23 |

- **صيغتان مختلفتان للأفواج** اكتُشفتا ودُعمتا: S1 يستعمل `الفوج X ( المجموعة a-b-c )`، أما S2 فيستعمل `الفوج X` مباشرة بلا مدى المجموعة → عولجتا معاً.
- مواد S1: 7 (مدخل لدراسة القانون/الشريعة، النظرية العامة للقانون الدستوري، الاقتصاد والتسيير، علم الاجتماع القانوني، علم السياسة، منهجية العمل الجامعي).

**برنامج التقويمات S1 (مؤكّد):** وحدات `M1 … M7` مربوطة بالأفواج (ABCDEF / GHIJKLM / NOPQRST) وأوقات رمضان/العادي.

### المخرجات المنظّمة (ملفات JSON)
- `ingest/out/structured/group_distribution.json` — 2 وثيقة (S2: 20 فوجاً، S4: 14 فوجاً) بنطاقات خام + الملحوظة.

### تعارضات وأمور تحتاج مراجعة بشرية (لم تُحسَم قسراً)
- نطاقات حدود الأفواج **تقريبية** (`A: A'MIL→AHACHTAR` ثم `B: AHACHTARI→…`): الحدّ الأدقّ يحتاج قائمة الألقاب الرسمية.
- في نصّ S1 ظهر `الفوج B (المجموعة 1-2-3)` مع أن B يفترض أن يكون `4-5-6` → **يُوسَم `needs_review`**.
- ربط الأستاذ↔القاعة↔الفوج صعب آلياً لتداخل خلايا الـPDF → لا يُنشر بلا مراجعة.

  - `imports` · `extracted_records` (منطقة انتظار قبل الاعتماد) · `conflicts` · `data_changes`

  - RLS: قراءة عامة للمنشور فقط، كتابة للمسؤولين عبر `public.is_admin()`، والجداول التابعة تُقرأ شرط كونها تابعة لصفّ منشور.
- ✅ **جسر الاستيراد → قاعدة البيانات: `ingest/to_sql.py`** — يحوّل `structured/*.json` إلى
  **إدخال في منطقة الانتظار** `extracted_records (status='pending')` داخل `imports`.
  - الناتج: `ingest/out/sql/seed_staging.sql` (تحقّق: UTF-8 صالح، 6 صفوف، 0 حمولة JSON تالفة، الهروب من `A'MIL` سليم).
- المبدأ المعتمد: **لا نشر آلي** — البنية تفصل «مستخرَج آلياً» عن «مُعتمَد من مسؤول».

## 6) المرحلة H — التشغيل محلياً

```powershell
# 1) الاستخراج من المصدر (مثال)
$proj = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'Default Project'
python "$proj\chrvvim-campus\ingest\extract.py" --src "G:\My Drive" --out "$proj\chrvvim-campus\ingest\out" `
  --include "استعمال الزمن" --include "توزيع أفواج" --include "تقويمات" --include "مقابل الوحدات"

# 2) التحليل إلى JSON
python "$proj\chrvvim-campus\ingest\parse.py" --text "$proj\chrvvim-campus\ingest\out\text" --out "$proj\chrvvim-campus\ingest\out\structured"

# 3) خادم المشروع (Node)
cd "$proj\chrvvim-campus"; npm install; npm run dev
```

**المتطلّبات:** Python 3 + `pypdf` (`python -m pip install pypdf`) · Node.js · لا مفاتيح سرّية في الواجهة.
