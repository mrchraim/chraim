# معمارية CHRVVIM CAMPUS

وثيقة موجزة تشرح البنية، دورة حياة الطلب، نموذج البيانات، والتحسين التدريجي.

---

## 1. نظرة عامة

المشروع نظام واحد بوجهين متكاملين:

```
                       ┌──────────────────────────────┐
                       │        الواجهة (web/)         │
                       │  بوابة الطالب + لوحة الإدارة   │
                       └───────────────┬──────────────┘
                                       │ fetch
             ┌─────────────────────────┴─────────────────────────┐
             │                                                     │
     (متوفّر خادم)                                      (نشر ثابت فقط)
             ▼                                                     ▼
   ┌───────────────────┐                              ┌────────────────────────┐
   │  خادم Node (API)   │                              │  ملفات web/data/*.json │
   │  + SQLite          │                              │  (مصدر مرجعي مضمّن)     │
   └───────────────────┘                              └────────────────────────┘
```

- **وضع API**: التطبيق يقرأ من `/api/public/*` (بيانات حيّة، قابلة للتعديل من لوحة الإدارة).
- **وضع ثابت**: عند غياب الخادم، تُشتق الجداول والمواد والأساتذة والقاعات من `academic-guide.json`.
- القرار يُتخذ تلقائياً في `web/assets/js/data.js` عند نجاح أو فشل نداء `/api/public/meta`.

## 2. الخادم

### دورة حياة الطلب (`server/index.mjs`)

كل طلب يمرّ بوسائط عامة (middlewares) قبل مطابقة المسار:

> عند الاستيراد يقرأ `server/config.mjs` الإعدادات من البيئة، ويحمّل ملف `.env` إن وُجد (بلا تبعية، مع أولوية لمتغيّرات البيئة الفعلية).

1. **رؤوس الأمان** (`securityHeaders`): CSP، `X-Frame-Options`، إلخ.
2. **الجلسة** (`loadSession`): تُقرأ من ملف التعريف، وتُنشأ جلسة جديدة لطلبات `/api/admin` عند غيابها.
3. **قراءة الجسم** (`readJsonBody`): للطلبات `POST/PUT/PATCH` مع حدّ أقصى (100KB).
4. **حماية CSRF** (`csrfGuard`): تتحقق من الرمز في كل الطلبات المعدّلة.

ثم:

- **مسارات `/api/*`**: مطابقة عبر `Router` وتشغيل سلسلة المعالجات (`runChain`).
- **الملفات الثابتة**: تُقدَّم من `web/` مع قواعد تخزين مؤقت حسب البادئة، وصفحة `404.html` عند الفشل (بحالة 404).

### المعالجات وسلسلة `next()`

- الموجّه يُرجع `{ params, handlers }` حيث ترتيب السلسلة: الوسائط العامة ثم معالجات المسار.
- كل معالج **يجب** أن ينادي `next()` للمتابعة؛ وإلا تتوقف السلسلة (سلوك نهائي مقصود لمعالجات المسارات).
- الأخطاء: `HttpError(status, message, extra)` تُترجم إلى JSON بحالة مناسبة. الأخطاء غير المتوقعة تُسجَّل (خارج الإنتاج) وتُعاد بحالة 500 دون كشف التفاصيل.

### الطبقات

| الطبقة | الملف | المسؤولية |
| --- | --- | --- |
| التوجيه | `lib/router.mjs` | مطابقة الطريقة/المسار + استخراج المعاملات |
| HTTP | `lib/http.mjs` | JSON، قراءة الجسم، تقديم الملفات (حماية من Path Traversal) |
| الأمان | `lib/security.mjs` | scrypt، رؤوس الأمان، حدّ المعدل، مقارنات ثابتة الزمن |
| الجلسات | `lib/session.mjs` | HMAC + مخزن SQLite + ملف تعريف ارتباط HttpOnly |
| قاعدة البيانات | `lib/db.mjs` | اتصال `DatabaseSync` + المخطط + المعاملات |
| التحقق | `lib/validate.mjs` | مخططات الحقول (رفض الحقول غير المعروفة) |
| الأحداث | `services/audit.mjs` | كتابة سجل التدقيق |
| الصياغة | `services/ai.mjs` | مزوّد LLM (Gemini/OpenAI/Groq/OpenRouter) + صياغة محلية، بلا تبعيات |

## 3. نموذج البيانات

### الجداول (SQLite)

| الجدول | الحقول الأساسية |
| --- | --- |
| `schedules` | semester, track, day, time, subject, professor, room, group_name, subgroups, status, source_note |
| `courses` | semester, track, name, professors, notes, status |
| `professors` | name, email, office, notes, status |
| `rooms` | name, building, capacity, notes, status |
| `announcements` | title, body, kind, starts_at, ends_at, status, created_by |
| `admins` | email, password_hash, role, active, last_login_at |
| `sessions` | id, admin_id, csrf_token, created_at, expires_at |
| `audit_logs` | admin_id, action, entity, entity_id, details, created_at |

- الحقول المشتركة `status ∈ {draft, published, archived}` و`updated_at` تُدار من الخادم.
- الواجهة العامة لا تُظهر إلا السجلات `published` (والإعلانات ضمن نطاقها الزمني).

### الملفات المرجعية (`web/data/`)

| الملف | الدور |
| --- | --- |
| `academic-guide.json` | المصدر الكامل: السداسيات، المسالك، الجداول، الأفواج، المسارات، التحقق |
| `academic-guide-public.json` | نسخة عامة مبسّطة |
| `academic-documents.json` | فهرس وثائق PDF |
| `founder-profile.json` | بيانات المؤسس |
| `site-config.json` | إعدادات الموقع: الروابط الرسمية + إعداد بوابة المتابعة (`gate.enabled`) |
| `announcements.json` | إعلانات مضمّنة (لوضع النشر الثابت) |
| `subjects-correspondence.json` | المواد والمقابلات: الأنظمة، المسالك، جدول الإقران، المواد (مع `confidence` و`rule`)، وعناصر المراجعة |
| `timetable-s3-draft.json` | مسودة السداسي الثالث (احتياطية؛ غير مُستوردة تلقائياً) |

**اشتقاق البيانات (وضع ثابت)**: `deriveSchedules`، `deriveCourses`، `deriveProfessors`، `deriveRooms`، و`collectRanges` في `web/assets/js/data.js` تبني نفس البنية من الدليل الأكاديمي، فتظل الواجهة مكتملة بلا خادم.

## 4. الواجهة

### البوابة العامة (`web/`)

- **بنية SPA بتوجيه hash** (بدون مكتبات): `app.js` يدير المسارات والأحداث، و`views.js` العرض، و`data.js` البيانات، و`i18n.js` الترجمة، و`store.js` التفضيلات، و`gate.js` بوابة المتابعة الاختيارية.
- **لوحات الواجهة**: ابحث عن فوجي، استعمال الزمن، المسالك، **المواد والمقابلات**، الدليل، **توزيع الأفواج**، الوثائق، **حاسبة المعدل**، الإحصائيات، عن المؤسس، والبطاقة القانونية/المصادر.
- **i18n** عربية/فرنسية/إنجليزية مع تبديل RTL/LTR.
- **التحسين التدريجي**: يعمل من JSON ثابت، ويرتفع إلى API عند توفّره.
- **PWA**: `manifest.webmanifest` + `sw.js` للتخزين المؤقت والعمل دون اتصال.
- **بلا سكربتات داخلية**: كل JS في ملفات `type="module"` (متوافق مع CSP `script-src 'self'`).
- **دمج الموقع السابق**: أُعيد إدخال ميزات البوابة الثابتة السابقة (توزيع الأفواج، حاسبة المعدل، البوابة، البطاقة القانونية، الإحصاءات في الترويسة، الخلفية الديناميكية، بطاقة فوجي المحفوظ، الخط الزمني/المشاريع، نسخ/طباعة الجدول) ضمن نفس البنية، فصار المشروع مجموعة شاملة (Superset) للموقعين.

### لوحة الإدارة (`web/admin/`)

- **مستقلة بالكامل**: HTML/CSS/JS مع ترجمة خاصة (ar/fr/en) ووضع ليلي.
- تتواصل مع `/api/admin/*`، وتُدير رمز CSRF تلقائياً (تُبادله عند الدخول وعند كل تغيير).
- تتبع الصلاحيات لإظهار/حجب أزرار الإجراءات (محرر/ناشر/مدير).
- صلاحيات الملفات مقيّدة بـ `noindex` (لا فهرسة).

## 5. مساعد الصياغة بالذكاء الاصطناعي

خدمة اختيارية (`server/services/ai.mjs`) تحوّل موضوعاً مختصراً إلى **مسودة إعلان** (عنوان + نص) داخل لوحة الإدارة، دون أي تبعية خارجية (تستعمل `fetch` المدمج).

### المسار

```
POST /api/admin/ai/draft   (requireLogin + rateLimit 20/دقيقة)
   └─ aiDraftSchema.parse({topic, kind, tone, language, notes})
        └─ generateDraft(input)
             ├─ الإعداد غير مفعّل؟  → localDraft()                 source=fallback
             ├─ نداء المزوّد (مهلة AI_TIMEOUT_MS)
             │     ├─ رد صالح (JSON) → sanitizeDraft()            source=ai
             │     └─ فشل/رد غير صالح → localDraft() (تراجع آمن)  source=fallback
             └─ audit(ctx, 'ai_draft', ...)
GET /api/admin/ai/status   → { configured, provider, model, fallback }
```

### المبادئ

- **مجرّد محض**: `resolveProviderConfig / normalizeInput / buildMessages / parseDraft / sanitizeDraft / localDraft` دوال خالصة قابلة للاختبار (بلا شبكة)، بينما `generateDraft` هو الوحيد الذي يستدعي الشبكة وقابل للحقن بـ `deps.fetch` في الاختبارات.
- **تدهور رشيق**: لا تعطّل اللوحة أبداً؛ أي خطأ (شبكة، HTTP، رد غير JSON، نص قصير) يتحوّل إلى الصياغة المحلية مع `source='fallback'`.
- **متوافق مع عدة مزوّدين**: Gemini (`systemInstruction/generateContent`) أو أي واجهة متوافقة مع OpenAI (`/chat/completions` + `Authorization: Bearer`).
- **بلا نشر تلقائي**: الناتج بيانات نموذج فقط؛ الحفظ/النشر إجراء بشري.
- **حدود**: العنوان ≤ 180 حرفاً والنص ≤ 5000 حرف (مطابقة لمخطط الإعلان).

## 6. الأمان بالتصميم

- **كلمات المرور**: `scrypt` مع Salt عشوائي (N=16384, r=8, p=1).
- **الجلسات**: معرّف عشوائي (32 بايت) موقّع بـ HMAC-SHA256، مخزّن في SQLite، في ملف تعريف `HttpOnly; SameSite=Strict`، مع تدوير عند الدخول.
- **CSRF**: رمز لكل جلسة يُقارَن بطريقة ثابتة الزمن في كل طلب معدّل.
- **حدّ المعدل**: دلو لكل (مفتاح + عنوان IP) — تسجيل الدخول 8/15 دقيقة، التعديل 120/دقيقة، الصياغة بالذكاء الاصطناعي 20/دقيقة.
- **التحقق**: رفض الحقول غير المعروفة والقيم الخارجة عن الشروط.
- **الملفات**: منع اجتياز المسار، وتقديم الأنواع المعروفة فقط.

## 8. اتخاذ القرار في الوضع المزدوج (API / ثابت)

```
loadAll()
  ├─ GET /api/public/meta  ── نجاح؟ ── نعم → apiAvailable = true
  │                                     لا  → apiAvailable = false
  ├─ guide     : API  أو  data/academic-guide.json
  ├─ documents : API  أو  data/academic-documents.json
  ├─ schedules : لكل سداسٍ: API (منشور) وإلا اشتقاق من الدليل
  └─ ...        : professors/rooms بنفس المنطق
```

بهذا التصميم يظل المشروع **قابلاً للنشر الثابت** بالكامل، مع إمكانية الترقية الفورية إلى نظام حقيقي مُدار دون تغيير أي كود واجهة.

## 9. المواد والمقابلات الجامعية (فصل البيانات عن المنطق عن العرض)

ميزة «المواد والمقابلات ديالي» مبنية على ثلاثة أجزاء مستقلة، حتى يمكن تحديث المواد بدون لمس الكود:

```
web/data/subjects-correspondence.json   ← البيانات (تُحرَّر يدوياً)
        │
        ▼
web/assets/js/subjects-engine.js        ← منطق صافٍ (بلا DOM): computeResult / progressOf / buildSms ...
        │
        ▼
web/assets/js/subjects-view.js          ← العرض والأحداث فقط (يستورد getData() من views.js)
        │
        ▼
web/index.html (لوحة #p-subjects) + app.js (ROUTES + renderSubjects) + i18n.js (مفاتيح subjects.* / sem.*)
```

### نموذج البيانات

- `pairings`: جدول الإقران `{from, to}` (مثال أوّلي: S1↔S3, S2↔S4, S3↔S5, S4↔S6).
- `tracks`: مسلك لكل `system` (نظام 2025/2026 ونظام 2023/2024).
- `subjects`: كائن لكل مادة: `{id, system, track, semester, name{ar,fr,en}, correspondsTo[], rule, confidence}`.
  - `correspondsTo`: قائمة معرّفات المواد المقابلة (يمكن أن تكون صفراً أو عدة).
  - `rule`: `equivalence | compensation | exemption | none | unknown`.
  - `confidence`: `confirmed | needs_review`.
- `review`: قائمة العناصر غير الواضحة (تُعرض للمستخدم في قسم «تحتاج مراجعة» بدل تخمينها).

### قواعد الأمان الأكاديمي في المنطق

- **لا إعفاء بلا قاعدة مؤكّدة**: إذا نجح الطالب في مادة لها مقابل وقاعدة المادة `unknown`، تُعرض المادة المقابلة كـ`state='review'` (تحتاج مراجعة)، لا كـ`eligible`.
- **حالة كل مادة**: ✅ اجتزتها / ❌ لم أنجح / ⏳ لم أُجرِ / ➖ غير معنية / ⬜ لم تُحدَّد.
- **المخرجات**: قسم المواد المستوفاة، قسم المواد المتبقية، قسم مواد السداسي المقبل (مع سبب كل مادة: جديدة / لها مقابل، ودرجة اليقين)، إضافةً إلى قائمة المراجعة وتنبيه صريح بأن النتائج مؤقتة.
- **رسالة SMS/WhatsApp**: تُبنى ديناميكياً من أسماء المواد الفعلية (بلا أي اسم مكتوب في الكود)، مع زرّي «نسخ الرسالة» و«مشاركة النتيجة».

### الخصوصية

- لا حساب إلزامي. الحفظ اختياري: لا يُكتب شيء في `localStorage` قبل موافقة المستخدم (`subjects.saveConsent`)، وزرٌّ «حذف بياناتي» يمسح كل شيء. لا تُطلب أسماء كاملة ولا أرقام تسجيل.
- تُحمَّل البيانات من `data/subjects-correspondence.json` مباشرةً (بلا مسار API)، فتعمل في وضع الخادم وفي النشر الثابت على حدٍّ سواء.
