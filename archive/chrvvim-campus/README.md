# CHRVVIM CAMPUS

بوابة طلابية متكاملة لكلية العلوم القانونية والسياسية — أكادير (جامعة ابن زهر): دلائل الأفواج، استعمال الزمن، المواد، الأساتذة، القاعات، الوثائق الرسمية والإعلانات، مع لوحة إدارة كاملة.

> منصة مستقلة غير رسمية. تحقق دائماً من الإعلانات والجداول الرسمية للكلية.

## الميزات

**البوابة العامة (واجهة الطالب)**

- 🔎 **ابحث عن فوجك** حسب اللقب (تطبيع ذكي للنص الفرنسي/العربي، مطابقة تامة وأولوية).
- 🗓️ **استعمال الزمن** الأسبوعي: عرض شبكي وقائمة، مع تصدير `.ics`، مشاركة، نسخ، وطباعة.
- 🧭 **المسالك والمسارات**: بنية كل المسارات (مواد + أساتذة + توزيع الأفواج).
- 📚 **الدليل الأكاديمي**: بحث شامل في المواد والأساتذة والقاعات مع مرشّحات (الكل/المواد/الأساتذة/القاعات).
- 🗂️ **توزيع الأفواج**: لوحة مستقلة تعرض جداول التوزيع (الأساسية/الإنجليزية/الفرنسية) لكل مسار في السداسي.
- 📄 **مركز الوثائق**: ملفات PDF الرسمية مع التصفية حسب السداسي والشعبة.
- 🧮 **حاسبة المعدل الموزون**: حساب فوري داخل المتصفح، مع إمكانية جلب مواد المسلك المختار.
- ⭐ **فوجي المحفوظ**: بطاقة سريعة للفوج/الأفواج المحفوظة محلياً.
- ⚖️ **بطاقة قانونية + مصادر رسمية**: روابط مباشرة لإعلانات الكلية الرسمية.
- 📊 **لوحة الإحصائيات** وملاحظات التحقق من المصادر، وترويسة بأرقام حيّة (مسارات/حصص/أساتذة/وثائق).
- 🎓 **المواد والمقابلات ديالي**: خريطة مواد الطالب بين السداسيات، وحالة كل مادة (✅ اجتزتها · ❌ لم أنجح · ⏳ لم أُجرِ · ➖ غير معنية)، مع شريط تقدّم وثلاثة أقسام نتائج (المستوفاة / المتبقية / مواد السداسي المقبل) ورسالة جاهزة للنسخ أو المشاركة. البيانات في ملف JSON مستقل، والمنطق في وحدة صافية، والعرض في وحدة واجهة؛ **لا يُصدر أي قرار إعفاء/تعويض قبل تأكيد القاعدة الرسمية** (يُعرض كـ«تحتاج مراجعة»).
- 🔓 **بوابة متابعة اختيارية** (معطّلة افتراضياً): قابلة للتفعيل من `web/data/site-config.json` (`gate.enabled`) لربط البحث بمتابعة إنستغرام.
- 🌗 **وضع ليلي**، 🌍 **ثلاث لغات** (العربية/الفرنسية/الإنجليزية)، 📱 **PWA** قابلة للتثبيت والعمل دون اتصال، وخلفية ديناميكية حسب القسم.

**لوحة الإدارة**

- 🔐 دخول آمن بجلسة مخزّنة في قاعدة البيانات ورمز CSRF.
- ✍️ إدارة كاملة (CRUD) للجداول، المواد، الأساتذة، القاعات، والإعلانات.
- 👥 إدارة الحسابات والصلاحيات (مدير / ناشر / محرر).
- 🧾 سجل تدقيق لكل العمليات الحساسة.
- ✨ **مساعد صياغة بالذكاء الاصطناعي** (اختياري): يولّد عنواناً ونصاً للإعلانات/التنبيهات من موضوع مختصر — بمزوّد خارجي عند توفّر مفتاح، أو **بصياغة محلية** منظّمة بلا إنترنت وبلا مفتاح. لا يُحفظ شيء تلقائياً: الناتج يُملأ في النموذج للمراجعة.
- 🚀 **نشر جماعي** لكل المسودات في نقرة.
- 🔄 **ترقية تدريجية (Progressive Enhancement)**: تعمل الواجهة من ملفات JSON ثابتة وحدها، وتتحول تلقائياً إلى API + قاعدة بيانات عند توفّر خادم Node.

## التقنية

- **بلا أي تبعيات خارجية**: Node.js (`node:http`, `node:sqlite`, `node:crypto`) + واجهة ES Modules خالصة.
- خادم HTTP مخصّص مع موجّه، وسائط (middleware)، وحماية CSRF/حدّ معدّل.
- قاعدة بيانات SQLite مدمجة (`DatabaseSync`) مع تهيئة تلقائية.
- كلمات المرور بـ `scrypt`، والجلسات موقّعة بـ HMAC في ملف تعريف ارتباط `HttpOnly`.

> يتطلب **Node.js ≥ 22.5** (لأن `node:sqlite` أصبح مستقراً في الإصدارات الحديثة).

## التشغيل السريع

```bash
# 1) تهيئة قاعدة البيانات وإنشاء أول حساب مدير
#    (عيّن كلمة مرور لا تقل عن 14 حرفاً)
#    Windows PowerShell:
$env:ADMIN_EMAIL="admin@example.com"; $env:ADMIN_PASSWORD="Change-Me-Now-2026!"; npm run seed

#    Linux/macOS:
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='Change-Me-Now-2026!' npm run seed

# 2) تشغيل الخادم
npm start
# ثم افتح http://localhost:3000  ولوحة الإدارة على http://localhost:3000/admin/
```

للتفعيل في الإنتاج، عيّن `SESSION_SECRET` (32 حرفاً على الأقل) و`NODE_ENV=production`.

## النشر الثابت على Netlify

البوابة تعمل بالكامل من ملفات JSON المضمّنة، لذا يمكن نشر مجلد `web/` وحده كموقع ثابت:

```bash
netlify deploy --prod
```

- إعدادات البناء موجودة في `netlify.toml` (`publish = "web"`).
- عند الواجهة الثابتة فقط: `apiAvailable = false` فيشتق التطبيق الجداول والمواد من `web/data/academic-guide.json`.
- عند توفّر خادم Node في الإنتاج: تتحول الواجهة تلقائياً إلى `/api/public/*` (بيانات حيّة من قاعدة البيانات).

### نشر «الموقع الحالي» الموحّد (نفس الرابط/الموقع المرتبط)

الموقع المرتبط موجود في جذر المشروع (`.netlify/state.json`)، ويوجد `netlify.toml` في الجذر يشير إلى واجهة هذا المشروع:

```toml
[build]
  base = "chrvvim-campus"
  publish = "web"
  command = "node scripts/check.mjs"
```

بالنشر من الجذر يُستبدل محتوى الموقع الحالي بالنسخة الموحّدة (البنية المتقدمة + كل ميزات الموقع السابق):

```bash
# من جذر المشروع (Default Project)
netlify deploy --prod
```

> ملاحظة: لوحة الإدارة تحتاج خادم Node (API + قاعدة بيانات)، ولا تعمل على النشر الثابت وحده.

## لوحة الإدارة

- الرابط: `/admin/`.
- الأدوار:
  - **مدير (admin)**: كل الصلاحيات (بما فيها الحذف وإدارة الحسابات).
  - **ناشر (publisher)**: إدارة المحتوى والنشر.
  - **محرر (editor)**: إنشاء/تعديل المسودات فقط.
- السجلات الجديدة تبدأ بحالة **مسودة** ولا تظهر للعامة حتى تُنشر.
- زر **نشر كل المسودات** متاح للمدير والناشر.

## مساعد الصياغة بالذكاء الاصطناعي

داخل نموذج تحرير **الإعلانات** تظهر لوحة «الصياغة بالذكاء الاصطناعي»: اكتب الموضوع واختر النبرة، فيُولَّد عنوان ونص جاهزان للتعديل قبل الحفظ.

- **مزوّدون مدعومون** (بلا أي تبعية خارجية — عبر `fetch` المدمج):
  - `gemini` (Google AI Studio)، `openai`، `groq`، `openrouter`، وأي مزوّد `custom` متوافق مع OpenAI.
- **بلا مفتاح**: يعمل المساعد تلقائياً بـ **صياغة محلية** منظّمة (قالب حسب النوع واللغة) — بلا إنترنت وبلا تكلفة. تبين اللوحة الوضع الحالي عبر شارة «ذكاء اصطناعي» أو «صياغة محلية».
- **بلا حفظ تلقائي**: الناتج يُملأ في الحقول فقط، والقرار النهائي للحفظ/النشر للمستخدم.
- **متين**: عند أي فشل في الشبكة أو رد غير صالح يتراجع تلقائياً للصياغة المحلية دون تعطيل اللوحة.

للتفعيل، عيّن في بيئة الخادم:

```bash
AI_PROVIDER=gemini
AI_API_KEY=...        # مثال: من Google AI Studio
# AI_MODEL=gemini-2.0-flash   # اختياري
```

> لوحة الإدارة (ومساعد الصياغة) تحتاج خادم Node؛ لا تعمل على النشر الثابت وحده.

## متغيرات البيئة

| المتغير | الوصف | الافتراضي |
| --- | --- | --- |
| `PORT` | منفذ الخادم | `3000` |
| `SESSION_SECRET` | مفتاح توقيع الجلسات (≥32 حرفاً في الإنتاج) | قيمة تطويرية |
| `DATABASE_PATH` | مسار ملف SQLite | `server/data/chrvvim.sqlite` |
| `NODE_ENV` | `production` لتفعيل HSTS/التحقق | — |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | أول حساب مدير عند `seed` | — |
| `AI_PROVIDER` | مزوّد الصياغة: `gemini` · `openai` · `groq` · `openrouter` · `custom` | `gemini` عند وجود مفتاح، وإلا `none` |
| `AI_API_KEY` | مفتاح المزوّد (بدونه تعمل الصياغة المحلية) | — |
| `AI_MODEL` | اسم النموذج | نموذج افتراضي لكل مزوّد |
| `AI_BASE_URL` | قاعدة الواجهة (للمزوّدات المتوافقة مع OpenAI/المخصّصة) | قاعدة المزوّد |
| `AI_TIMEOUT_MS` | مهلة نداء المزوّد بالملّي ثانية | `20000` |

انسخ `.env.example` إلى `.env` بجانب `package.json`؛ **يُحمَّل تلقائياً** عند تشغيل الخادم (بلا أي تبعية)، مع بقاء أولوية متغيّرات البيئة المُمرَّرة فعلياً على قيم الملف.

## واجهة API

**عامة (قراءة فقط)**

| المسار | الوصف |
| --- | --- |
| `GET /api/public/health` | فحص صحة الخدمة |
| `GET /api/public/meta` | بيانات وصفية + قدرات + إحصائيات |
| `GET /api/public/guide` | الدليل الأكاديمي الكامل |
| `GET /api/public/documents` | الوثائق الرسمية |
| `GET /api/public/founder` | بيانات المؤسس |
| `GET /api/public/site-config` | إعدادات الموقع (الروابط الرسمية + بوابة المتابعة) |
| `GET /api/public/announcements` | الإعلانات المنشورة |
| `GET /api/public/schedules?semester=&track=&group=` | الحصص المنشورة |
| `GET /api/public/courses?semester=` | المواد المنشورة |
| `GET /api/public/professors` · `GET /api/public/rooms` | الأساتذة / القاعات |

**إدارية (تتطلب جلسة + رمز CSRF للطلبات المعدّلة)**

| المسار | الوصف |
| --- | --- |
| `GET /api/admin/csrf` | الحصول على رمز CSRF للجلسة |
| `POST /api/admin/login` · `POST /api/admin/logout` | الدخول / الخروج |
| `GET /api/admin/me` | حالة الجلسة |
| `GET/POST/PUT/DELETE /api/admin/{entity}` | CRUD (`schedules`, `courses`, `professors`, `rooms`, `announcements`) |
| `POST /api/admin/{entity}/publish-all` | نشر كل المسودات |
| `GET/POST/PATCH /api/admin/users` | إدارة الحسابات (مدير) |
| `GET /api/admin/ai/status` | حالة مساعد الصياغة (مفعّل/محلي) |
| `POST /api/admin/ai/draft` | توليد مسودة إعلان (`{topic, kind, tone, language, notes}`) |
| `GET /api/admin/audit` | سجل التدقيق (مدير) |

## الأمان

- كلمات المرور مُجزّأة بـ `scrypt` (Salt عشوائي لكل كلمة).
- الجلسات: معرّف عشوائي + توقيع HMAC-SHA256 في ملف تعريف ارتباط `HttpOnly` + `SameSite=Strict`.
- تدوير الجلسة عند الدخول (منع تثبيت الجلسة).
- حماية CSRF عبر رمز مرتبط بكل جلسة.
- حدّ معدّل على تسجيل الدخول والعمليات المعدِّلة.
- رؤوس أمان: CSP، `X-Frame-Options`، `X-Content-Type-Options`، `Referrer-Policy`، إلخ.
- الحماية من هجمات اجتياز المسار (Path Traversal) عند تقديم الملفات.
- تحقق صارم من المدخلات (رفض الحقول غير المعروفة).

## التحقق من البيانات

- البيانات مبنية على وثائق ومخططات مقدَّمة من المستخدم (2026/2027)، مع الإشارة إلى ملاحظات التحقق في `web/data/academic-guide.json` (الحقل `verification`).
- يوجد تعارض مؤجَّل في توقيت بعض حصص السداسي الثالث بين المصادر، وهو موثَّق للمراجعة.
- المصدر المرجعي الكامل: `web/data/academic-guide.json`.

## SEO والظهور في محركات البحث

- `web/index.html` يتضمّن: `robots`، `author`، `canonical`، Open Graph، Twitter Card، وJSON-LD (`WebSite`).
- ملفات مُولَّدة في `web/` عبر `node scripts/seo.mjs`:
  - `robots.txt` (يسمح بالفهرسة ويمنع `/admin`).
  - `sitemap.xml`.
  - `security.txt` و`.well-known/security.txt` (RFC 9116).
- النطاق الأساسي مأخوذ من متغيّر البيئة `SITE_URL`، ثم `URL`/`DEPLOY_PRIME_URL` من Netlify، وإلا القيمة الافتراضية داخل `scripts/seo.mjs`.
- لتغيير النطاق:

```bash
SITE_URL="https://example.netlify.app" node scripts/seo.mjs
```

أمر البناء في `netlify.toml` يشغّل: `node scripts/check.mjs && node scripts/seo.mjs`.

## إتاحة الوصول (a11y)

- تبويبات الصفحة بأدوار ARIA (`tablist` / `tab` / `tabpanel`) وتنقّل بلوحة المفاتيح (الأسهم، Home، End) مع احترام الاتجاه RTL.
- `prefers-reduced-motion` يوقف الحركات والانتقالات.
- رابط تجاوز إلى المحتوى وتركيز مرئي واضح.

## دخول لوحة الإدارة (مخفي)

لا يوجد أي رابط ظاهر للوحة. ثلاث طرق للدخول:

1. اختصار لوحة المفاتيح: `Ctrl`/`Cmd` + `Shift` + `A`.
2. ثلاث نقرات متتالية على تذييل الصفحة.
3. فتح الرابط `#admin` (مثال: `/#admin`).

هذا إخفاء فقط؛ الأمان الحقيقي هو مصادقة الخادم وصلاحيات الجلسة.
