## 2. Bugs found & fixed (all committed locally @ `30c222b`)

### BUG-1 — `npm test` was completely broken  🔴 HIGH
`package.json` → `"test": "node --test tests/"`.
On Node v24 this aborts with `MODULE_NOT_FOUND: ...\tests` → **0 tests ran, exit 1**.
**Fix:** `"test": "node --test tests/*.test.mjs"` → **62/62 pass, exit 0** (verified).

### BUG-2 — Production could silently run on a public session secret  🔴 HIGH (security)
`server/config.mjs` fell back to `'development-only-secret-…-000000'` (61 chars) and only threw when
`isProd && length < 32`. The fallback is longer than 32 → **the check never fired**; a production
deploy with `NODE_ENV=production` and no `SESSION_SECRET` would sign every session cookie with a
secret visible in the public repo → session forgery.
**Fix:** explicitly require an operator-supplied `SESSION_SECRET` in production (absent / <32 chars /
equal-to-default → throw). Dev unchanged.
**Verified:** `NODE_ENV=production node -e "import('./server/config.mjs')"` → blocked; dev → loads.

### BUG-3 — SEO metadata pointed at a dead domain  🟠 MEDIUM
`scripts/seo.mjs` (runs on every Netlify build) had
`DEFAULT_SITE = 'https://chrvvim0k0l0a0k0.netlify.app'` — a **503 site**.
The committed `web/index.html` had `og:url`, `og:image`, `twitter:image` → that dead host, so every
social share and search-engine signal referenced a non-resolving site.
**Fix:** default → `https://mr1mohamed1chraim.netlify.app` (live primary). Netlify's `URL` /
`DEPLOY_PRIME_URL` env still override it automatically on real deploys.

### BUG-4 — Relative canonical + relative JSON-LD `url`  🟠 MEDIUM
`<link rel="canonical" href="/">` and `"url":"/"` in JSON-LD.
On a sub-path deploy (GitHub Pages `/chrvvim-ai-hub/`) `/` resolves to the **wrong page**, risking
de-indexing; ambiguous for crawlers generally.
**Fix:** absolute `${SITE}/` for canonical and JSON-LD `url`; added `og:image:alt` /
`twitter:image:alt`.

### BUG-5 — Google verification tag present live but missing from repo  🟠 MEDIUM
Live primary C serves `google-site-verification: w-3dpQmT4vZKLaQzWiItSqIEMcUTB1PwukyMNctr8Uk`,
but `chrvvim-campus/web/index.html` did **not** contain it → **any redeploy from this repo would
strip verification**.
**Fix:** tag added to `web/index.html` **outside** the `seo:urls` marker block, so `seo.mjs` cannot
clobber it. Bing insertion point left as an explicit comment (no invented token).

## 3. Security review — findings

| Area | Verdict | Evidence |
|------|---------|----------|
| Password storage | ✅ PASS | scrypt (N=16384) + per-user salt, timing-safe compare |
| Session cookies | ✅ PASS | HMAC-SHA256 signed, HttpOnly, `SameSite=Strict`, `Secure` in prod, sliding TTL |
| Session fixation | ✅ PASS | session destroyed + recreated on login |
| CSRF | ✅ PASS | token required on all POST/PUT/PATCH/DELETE — smoke test proves 403 without it |
| AuthN / AuthZ | ✅ PASS | server-side role check re-reads DB each request; disabled account ⇒ session killed |
| Input validation | ✅ PASS | strict schemas, unknown fields ⇒ 400 (smoke-verified) |
| Path traversal | ✅ PASS | `sendFile` normalises + `startsWith(root+sep)` allow-list |
| SQL injection | ✅ PASS | parameterised statements throughout |
| XSS | ✅ PASS | `esc()` covers `& < > " '`; used for every dynamic `innerHTML` |
| Security headers | ✅ PASS | CSP, `X-Frame-Options: DENY`, HSTS, nosniff, Referrer-Policy, Permissions-Policy |
| Secrets in repo | ✅ PASS | `.env`, `*.sqlite`, `node_modules/`, `*.zip` all git-ignored |
| Rate limiting | ⚠️ RESIDUAL | login limiter keyed on `x-forwarded-for[0]` — spoofable when not behind a trusted proxy. Left unchanged (changing it risks breaking real proxy deployments); documented. |
| Body double-decode | ⚠️ LOW | `pathname` decoded, then `sendFile` decodes again — a literal `%` in a filename could 500. Cosmetic; no such file exists. |
