## 2. BUG-6 — `fetch("null")` → guaranteed 404 on every page (FIXED) 🟠 MEDIUM

`chrvvim-campus/web/assets/js/data.js`

```js
const courseData = await getJson(apiPath('/api/public/courses'),    null); // staticPath = null
const profData   = await getJson(apiPath('/api/public/professors'), null);
const roomData   = await getJson(apiPath('/api/public/rooms'),      null);
```

`getJson()` falls through to `tryJson(staticPath)`. When the API is not reachable (`apiPath()` → `null`),
`tryJson(null)` ran `fetch(null)` → the browser resolves it to the relative URL `…/null` → **404 ×3
per load**.

**Fix:** `if (!path) return null;` at the top of `tryJson()`.
**Verified:** `npm run check` → 0 errors/0 warnings · `npm test` → 62/62 pass · live browser load → 0 failed requests.

## 3. Findings investigated and deliberately NOT "fixed"

### 3.1 `/api/public/meta` 404 each load — BY DESIGN (not a bug)
`data.js` probes `/api/public/meta` to decide `apiAvailable`. `server/index.mjs` serves `web/` from
`WEB_DIR`, so the **same** `web/` folder runs in two modes:
- Node server mode → `/api/public/*` exists → probe **200** → live data used;
- static hosting (GitHub Pages / Netlify publish) → probe **404** → graceful fallback to the static JSON.

The 404 is the *capability-detection mechanism itself*. A static `runtime-config.json { "api": false }`
was considered and **rejected**: it would disable the API in the Node-server deployment (regression).
Conclusion: leave as-is; the fallback is correct and the failure is handled.

### 3.2 Merging the 23 extra PDFs from the legacy build — REJECTED (data-integrity risk)
`chrvvim-ai-hub/site/documents` (33 PDFs) carries documents the modern app lacks (S1, S3-private,
S5 business/admin-finance, French, 5 `learn-*` study guides). The titles are real (they exist in the
legacy `campus-data.js`), so importing would **not** be fabrication.

**But** the two catalogs name the same documents differently and sometimes represent different
*versions*, e.g.:
- modern: `s3-public-law-timetable-**updated-2026-10-10**.pdf`
- legacy: `s3-public-timetable.pdf`

Blind import risks surfacing **superseded timetables** to students. Per the rule "request reliable
source data rather than guess", this stays a **proposal requiring your confirmation**, not an edit.
