## 4. إجراء النسخ الاحتياطي (للمرحلة 2 وما بعدها)

قبل أي تعديل على المصدر، قاعدة البيانات، إعدادات النشر، أو التكاملات:

### الخطوة 1: إنشاء نسخ احتياطية منفصلة لكل مكون

```bash
# من جذر المشروع (مثال PowerShell):
# نسخ مجلد المشروع الرئيسي
Compress-Archive -Path "chrvvim-campus\*" -DestinationPath "_backups\CHRVVIM_backup_YYYY-MM-DD_main.zip"

# نسخ إعدادات النشر
Copy-Item "netlify.toml" "_backups\netlify.toml_YYYY-MM-DD"
Copy-Item ".netlify\state.json" "_backups\state.json_YYYY-MM-DD"

# نسخ ملفات الجذر الأخرى إن وجدت
Copy-Item "dist-ultra.zip" "_backups\dist-ultra_YYYY-MM-DD.zip"
```

### الخطوة 2: فصل الملفات الأصلية عن ملفات التطوير

```
_backups/                 # النسخ الأصلية فقط (لا تُلمس)
_development/             # نسخة عمل للتعديلات (تُنشأ من النسخة الأصلية)
_tests/                   # نتائج الاختبارات
_releases/                # الإصدارات المعتمدة للنشر
```

### الخطوة 3: جرد الملفات والتوثيق

تسجيل كل ملف مع:
- المسار والغرض
- الاعتمادات (ملفات تعتمد عليه)
- تاريخ الإنشاء/التعديل
- حالة التحقق (salient/غير مؤكد)

## 5. إجراء الاستعادة (Recovery Procedure)

### استعادة المشروع الرئيسي (`chrvvim-campus/`)

1. توقف عن أي عملية نشر أو تعديل جارية.
2. تأكد من وجود النسخة الاحتياطية الصالحة في `_backups/`.
3. أنسخ النسخة الاحتياطية فوق مجلد العمل الحالي (أو استعدها إلى مجلد جديد للمقارنة).
4. استعد `netlify.toml` و `.netlify/state.json` إلى جذر المشروع إن كانا قد تغيرا.
5. تحقق من سلامة الملفات باستخدام `node scripts/check.mjs` (يتطلب Node.js ≥ 22.5).
6. شغل اختبار الدخان `node scripts/smoke.mjs` على قاعدة بيانات مؤقتة (يتطلب Node.js).
7. قارن النسخة المستعادة بالنشرة الحية إن وجدت.
8. فقط بعد النجاح، أعد نشر الملفات (بموافقة المؤسس).

### استعادة قاعدة البيانات SQLite

```bash
# إيقاف الخادم إن كان يعمل
# نسخ احتياطي للقاعدة الحالية (إن وُجدت تغييرات غير محفوظة)
copy "server\data\chrvvim.sqlite" "_backups\chrvvim.sqlite_before_restore_YYYY-MM-DD"

# استعادة من النسخة الاحتياطية
# (فك ضغط ملف ZIP يحتوي على server/data/chrvvim.sqlite إلى المسار الأصلي)
```

### استعادة الموقع الحي (Netlify)

1. الدخول إلى لوحة تحكم Netlify للموقع المرتبط.
2. استخدام "Site settings" → "Deploys" لإرجاع الإصدار السابق (Rollback).
3. أو رفع المجلد `web/` من النسخة الاحتياطية عبر "Deploy" → "Manual deploy".
4. التحقق من أن النطاق العام يعمل (200 OK) وليس 503.

### استعادة الموقع 2 (`mrchraimfsjpachrvvim.netlify.app`) — جديد 2026-10-16

مصدر هذا الموقع محفوظ محلياً في `_archive/site2-mrchraimfsjpachrvvim/` (مستخرج من `dist-ultra.zip`):

1. ✅ المصدر متاح: المجلد يحتوي `index.html`, `app.js`, `admin.html`, `subjects.js`, `legal.js`, `supabase-config.js`, `campus-data.js`, `public/` (وثائق + خطوط + أيقونات).
2. ⚠️ **فحص قبل أي نشر:** راجع `announcements.json` (تم فحصه: إعلانان ثابتان فقط — لا بيانات شخصية) و`supabase-config.js` (مفتاح publishable عام فقط — لا service_role).
3. ⚠️ **مقارنة البيانات:** `academic-guide-2026-2027.json` و`academic-guide-public.json` في الأرشيف **تختلفان** عن نظيريهما في المشروع الموحّد — تُحسم أولويتهما قبل الدمج.
4. لإعادة النشر (فقط بموافقة صريحة): أنشئ موقعاً/نطاقاً مستقلاً وأرفع محتوى المجلد عبر Netlify.
